#UI/UX Design #Web app

著者専用ポータルサイト

出版作家向けの文書管理をデジタル化するSalesforce Experience Cloudポータル

Summary

契約書・請求書・支払明細を一元管理できる、作家向けのデジタルポータル。
紙を中心とした従来の事務手続きを、Salesforce Experience Cloud上のより使いやすいデジタル体験へ移行した。
リサーチ、必要なコンテンツ、ユーザーフローはクライアント側ですでに定義されていたため、既存のUX方針をもとに、ビジュアルシステムと実装可能なUIへ落とし込むことを担当した。

My Role

UI/UX Designer & Frontend Developer

初期のUX方針とワイヤーフレームが確定した段階からプロジェクトに参加した。

担当範囲：

  • 既存ワイヤーフレームのブラッシュアップ
  • 既存ワイヤーフレームをもとにしたUIシステムの構築
  • 全画面およびレスポンシブデザインの設計
  • HTML・CSS・JavaScriptによるフロントエンド実装
  • クライアント側のSalesforce実装チームとの連携
  • Salesforceの技術的制約に合わせたデザイン調整

初期ワイヤーフレームは別のUXデザイナーが作成し、その後のUI設計を引き継いだ。実装ではフロントエンド担当者から技術的なアドバイスを受けながら進行した。Salesforceへの実装およびバックエンド連携はクライアント側が担当した。

The Problem

作家は、契約書・請求書・支払明細など、仕事に関わる重要な書類を管理する必要がある。従来の業務は紙を中心とした運用で、一元化されたデジタル体験として設計されていなかった。また、日常的にデジタルサービスを利用しない作家も含まれるため、幅広いデジタルリテラシーに対応する必要があった。

Challenge
Salesforce上での使いやすさを保ちながら、出版社独自のブランド性を感じられる、わかりやすく親しみやすいUIをどう設計するか。

Project goals

  • 必要な書類をすぐに見つけられるようにする
  • デジタルリテラシーの違いによる認知負荷を減らす
  • 書類の種類をまたいで一貫したUIパターンを構築する
  • デスクトップ・モバイルの両方で快適に利用できるようにする
  • Salesforceの使いやすさを保ちながら出版社のブランドを表現する
  • Salesforceの環境に安定して実装できるUIシステムを構築する

The opportunity

既存のエンタープライズUIで使われている馴染みのあるパターンをベースとして活用することで、まったく新しい操作方法を学習する負担を減らせると考えた。

Target Users

出版社との仕事に関する書類を管理する作家が主なユーザーである。日常的にオンラインの事務サービスを利用する人から、デジタルツールにあまり慣れていない年配の作家まで、さまざまなユーザーが含まれる。

Authors managing administrative documents

主なニーズ：

  • 必要な書類をすぐに見つける
  • 専門知識がなくても情報を理解する
  • 支払いや契約内容を確認する
  • 異なるデバイスから快適にアクセスする

そのため、明快さ・親しみやすさ・低い認知負荷を優先したUI設計とした。

User Flow

全体のユーザーフローと情報設計は、プロジェクト参加時点ですでにクライアント側で定義されていた。そのため、既存のフローをもとに各画面のUI設計とインタラクションを具体化した。

Design System

Building a UI System from Existing Wireframes

初期ワイヤーフレームでコンテンツと基本構造が定義されていたため、そこからUIデザインを引き継ぎ、ポータル全体のビジュアルシステムを構築した。

特に以下の要素の一貫性を重視した。

  • Typography
  • Color
  • Spacing
  • Buttons
  • Cards
  • Tables
  • Form elements
  • Navigation
  • Status indicators
  • Responsive behavior

各画面の使い方を事前に学習しなくても内容を理解できることを目指した。

Typography & Information Hierarchy

管理情報をすばやく読み取る必要があるため、可読性を重要な要素として設計した。

  • 明確なタイポグラフィ階層
  • ゆとりのある余白
  • 情報のグルーピング
  • 一貫したアライメント
  • 状態を区別する視覚表現

これらにより、システムの構造を理解しなくても必要な情報を直感的に把握できるUIを目指した。

Responsive Design

デスクトップとモバイルの両方で利用できるよう、レスポンシブデザインを設計した。モバイルでは限られた画面領域を有効活用しながら、目的地を認識しやすいナビゲーションを設計した。アイコンとテキストラベルを組み合わせて発見性を維持し、スクロールに応じてナビゲーションを制御することで、画面を圧迫せず必要な操作へアクセスできるようにした。

Hi-Fi Screens

Dashboard

ポータルの主要機能へアクセスするためのシンプルな起点となる画面。システムの構造ではなくユーザーの目的ごとに情報をグルーピングし、必要な場所をすぐに見つけられるようにした。出版社のブランド性も、最初の画面から感じられるように設計した。

Document Lists

契約書・請求書・支払明細には共通したリストパターンを採用した。書類の種類が変わっても同じ操作感を維持することで、認知負荷を軽減した。主要な情報をすばやく確認し、必要な書類を選択できる構成とした。

Onboarding Screens

最初のステップで個人情報と連絡先を入力する。プログレスインジケーターによって現在のステップと残りのステップを明確に示した。住所入力では、日本以外の国を選択すると日本固有の住所項目を自動的に無効化し、不要な入力を求めない設計とした。

Mobile Experience

デスクトップと同じ情報階層を維持しながら、モバイルではナビゲーションとコンテンツ量を最適化した。単純にデスクトップのレイアウトを縮小するのではなく、限られた画面サイズでも重要な情報と操作を維持することを重視した。

Frontend Implementation

承認されたUIデザインをもとに、HTML・CSS・JavaScriptでレスポンシブなフロントエンドを実装した。

Salesforceチームと密に連携し、Salesforce環境の技術的制約に対応しながら、承認されたデザインシステムとの一貫性を維持した。実装中はフロントエンド担当者から技術的なアドバイスを受け、制約への対応やクライアント側のSalesforce実装との連携を進めた。

Results

契約書・請求書・支払明細を一元管理できるデジタルポータルを構築した。

最終的なデザインでは、

  • 紙を中心とした分散した書類管理をデジタル体験へ移行
  • ポータル全体で一貫したUIパターンを構築
  • 異なるデジタルリテラシーに配慮した可読性を実現
  • Salesforce環境に出版社のブランド性を反映
  • デスクトップ・モバイルに対応したレスポンシブUIを実現
  • 承認済みのUX構造を実装を見据えたUIシステムへ展開

エンタープライズプラットフォームの制約の中でも、UIデザインによって使いやすさとブランド価値を両立できることを示したプロジェクトとなった。

明快さを起点に、一貫性を構築し、
ユーザーの邪魔をせずにビジュアルデザインで価値を加える。

本プロジェクトを通して、実際の技術的制約の中でデザインを成立させる力を磨いた。
特に、既存のUX方針やSalesforceというプラットフォームの制約を尊重しながら、UIデザインによって使いやすさとブランド性を高める経験を得た。
